**逐条读法：**

1. **λ_D 覆盖胜过把对偶训起来（227.51 vs 233.11 kJ）。** S1 的对偶确实动起来了
   （λ_D 1.142 → 3.25），但它会**超调**：`budget = 0.01` 下上升速率是下降速率的 4 倍，
   而策略又在追一个移动的 λ，两者叠加使能耗回升（ep1200 时 246.99 kJ）。
   实用建议是两阶段：先用修好的对偶找到 λ*，再**冻结 λ** 微调。

2. **S4 的 DVFS 感知状态没有带来收益（诚实的负结果）。** 上层单独看有 1.75 kJ 优势
   （232.12 vs 233.87），在噪声内；而两臂的 SAC 配对节能都是**负的**。
   原因见第 4 节：这个问题实例的下层可行空间本来就接近于零。

3. **S2 vs S2ctl：一旦可靠性约束真正生效，低层奖励的量纲就不再重要。**
   两臂都被推到 ρ ≈ 0.99，节能都在噪声内。
   （在可靠性对偶修好**之前**，二者差别极大——见 §5，那才是 z-score 机制的证据。）

## 4. 下层的可行空间上界（零训练成本，决定性）

在冻结的 ep300 上层 + λ_D=2 上，直接播放开环 DVFS 策略：

**(a) 全体服务器均匀 ρ**

| ρ | Deadline | 可靠性成功率 | 平均可靠性 | 能耗 (kJ) | 双约束可行 |
|---:|---:|---:|---:|---:|:--:|
| 1.00 | 99.50% | 100% | 0.9421 | **229.85** | ✓ |
| 0.98 | 99.25% | 100% | 0.9379 | 231.77 | ✓ |
| 0.96 | 98.25% | 99.75% | 0.9332 | 231.94 | |
| 0.94 | 97.50% | 99.75% | 0.9282 | 235.57 | |
| 0.92 | 96.25% | 96.00% | 0.9229 | 237.13 | |
| 0.90 | 95.00% | 89.25% | 0.9172 | 239.20 | |
| 0.85 | 87.50% | 49.25% | 0.9005 | 244.06 | |

**(b) 选择性 DVFS**：`ρ_j = 1 − blend·(1 − ρ*_j)`，ρ*=1 的 edge_lowend 保持 ρ=1，
只降 DVFS 有利的服务器：

| blend | Deadline | 可靠性成功率 | 能耗 (kJ) | ρ_mean |
|---:|---:|---:|---:|---:|
| 0.00 | 99.50% | 100% | **229.85** | 1.000 |
| 0.10 | 98.75% | 100% | 232.25 | 0.962 |
| 0.20 | 97.25% | 98.75% | 236.79 | 0.926 |
| 0.30 | 95.25% | 86.00% | 241.23 | 0.892 |
| 0.50 | 88.00% | 16.50% | 257.97 | 0.831 |

**在这个问题实例上，不存在任何开环降频策略能降低系统能耗。**
能耗对 ρ 单调递减方向为 ρ→1，在每一个幅度、每一种选择方式下都成立。

原因（边际分解，ρ=1→0.98）：
- 固定放置下的直接 DVFS 节能 = **−3.1 kJ/seed**
  （edge_efficient −36.8、cloud_fast −17.7、cloud_standard −6.7、edge_legacy −5.1、edge_lowend **+4.2** kJ / 20 seeds）
- 实测系统变化 = **+1.9 kJ/seed**
- ⇒ 队列/重分配外部性 = **+5.0 kJ/seed**，比直接节能大 1.6 倍

服务器构成决定了这个结果：edge_lowend（ρ*=1.0，降频**更费电**）占 21.8% 能耗，
edge_legacy（ρ*=0.90，最多省 1.1%）占 29.8%，二者合计 **51.6%**。
真正 DVFS 友好的 cloud_fast + edge_efficient 只占 42%，而它们同时是队列最紧的服务器。

**因此：**

> "下层 SAC 降频很少"**不是 bug，而是这个问题实例的正确答案。**
> 而且 SAC 的策略在**定性上是对的**：cloud_fast 0.873 < edge_efficient 0.956 < edge_lowend 0.986，
> 恰好是 ρ* 的排序。它做的是**状态条件化的选择性降频**——只在队列有余量时降——
> 这是唯一能取得**正的**系统节能（+2.34 kJ，13/20 种子，CI 不含 0）的做法，
> 而**每一个**开环频率、**每一种**选择方式都使系统更差。

这本身就是一个可写进论文的结论：不是"我们让下层降得更多"，
而是"我们证明了下层的可行空间有多小，并且只有状态条件化的下层策略能落在正的那一侧"。

S2 与对照组配置**逐字相同，只差 `agent.physical_low_reward` 一个开关**：

|---:|---:|---:|
| 1 | 0.897 | 0.897 |
| 121 | 0.773 | 0.911 |

对照组精确重演了历史轨迹（0.95 → 微降 → 爬回 0.96+）。这是 E4 的直接实验证据。

说明真正的绑定约束是可靠性，不是奖励量纲。

## 6. 双头 / 三头消融（问题 5）

推理期把 λ_R 置 0（等价两头），同 20 seeds，冻结 ep300：

| 指标 | λ_R=1（三头） | λ_R=0（两头） |
|---|---:|---:|
| Deadline | 0.96750 | 0.96750 |
| 可靠性成功率 | 1.00000 | 1.00000 |
| 平均工作流可靠性 | 0.94192 | 0.94190 |
| 能耗 | 215445 J | **215185 J（低 0.12%）** |

**在 ρ=1 的轨迹上，可靠性头没有可测收益，还多花 0.12% 能耗。**

但由 E12 + §4：这只在"下层不工作"时成立。一旦下层真降频，可靠性立刻成为
**决定工作点的那个约束**（ρ<0.96 就开始违约，ρ=0.85 时成功率只有 49%），比 Deadline 更早生效。
所以正确的表述是：

> 可靠性头之所以看起来没用，正是因为下层 SAC 没在工作。
> 它是这个分层结构在**真正开始降频之后**才被激活的约束，
> 也是下层可行空间为什么这么小的直接原因之一。

## 7. 已知局限（必须写进论文的诚实部分）

1. **S1 的对偶超调**：`deadline_budget = 0.01` 使上升速率是下降速率的 4 倍，
   λ_D 会冲过最优值且难以回落。建议两阶段：对偶找 λ*，然后冻结 λ 微调。
2. **低层可靠性对偶的 windup**：`reliability_budget = 0` 时 λ 单调不降。
   改用二元违约率 + `budget = 0.005` 后可双向，但仍偏保守（把 ρ 推到 0.99）。
3. **跨工作流 bootstrap 未修**（E7）：Q_D 仍有 90% 是与动作无关的共模项。
   本轮没有动它，因为它需要同时改 replay 写入和 TD target，会破坏归因。
4. **`deadline_positive_fraction` 是死配置**（E6）：应清理，但不应作为改进手段
   （天然正样本比例 0.648 > 配置的 0.30，接回反而会降低违约样本曝光）。
5. **S3/S4 的 DVFS 感知状态是负结果**，不应写成正面贡献。
6. 上述所有结论都在 Small 数据集、26 台服务器、这一组功耗参数下成立。
   服务器构成（51.6% 的能耗在 DVFS 无益的机器上）是决定性因素，换数据集需重测。
