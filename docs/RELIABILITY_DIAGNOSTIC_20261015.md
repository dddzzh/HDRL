# 可靠性达标率饱和：诊断实验协议

## Research Question Card

- Question：当前可靠性达标率100%来自指标实现错误、物理模型与运行频率的余量，还是训练中可靠性成本确实参与了约束学习？
- Type：exploratory；解释已有结果，不以获得失败或全成功为目标。
- Hypothesis：当前冻结策略频率较高，测试可靠性约束可能不活跃；训练探索阶段仍可能触发可靠性约束。
- Current evidence：原始未筛选三资源模型共540条记录均达到可靠性门槛；平均R约0.997，但尚无逐工作流最小值证据。原始DReaM存在可靠性不达标，指标并非常数。
- Missing evidence：逐任务公式复算、逐工作流尾部裕量、训练成本/对偶活跃度、固定放置降频风险曲线。
- Support：独立复算一致，实际R尾部仍明显高于0.9，且频率降低消耗风险预算。
- Falsification：公式复算不一致；出现未披露的失败/遗漏工作流；实际R尾部接近或低于0.9。出现不一致时停止，不调整参数掩盖。
- Minimal next action：只读分析原始2160条记录和已有Full训练日志；固定74台Large/Tight原始20种子补存详细轨迹。
- Decision：run diagnostic；不启动消融训练，不修改科学模型或正式主表。

## 冻结范围与判据

1. 输出独立目录 `results/reliability_diagnostic_20261015`，原始/条件筛选结果、checkpoint、训练配置均不覆盖。
2. 使用 `panel_plan.json` 仅定位并核验原始12模型来源与hash；不使用其筛选种子名单。审计原始12×180=2160条记录。
3. 详细轨迹：原74台Full checkpoint，第1200轮，SHA256 `32764207f74371ae00c0c3cfdf9c16bd760c0a3143be560dd7f72f2ec1c652ea`；配置 `configs/v3_sm_74_new_eval_50wf.json`，Large/Tight、50工作流、到达率0.03/s、seed742000–742019，初始化742000、服务器seed42。
4. 这是已知测试集上的诊断复放，不是新增独立泛化证据；20种子全部保留，不替换或按结果追加。
5. 复放每条记录与原始同键指标核对；独立复算 `lambda(rho)`、`exp(-lambda*t)`、任务可靠性乘积及每批达标率，并核验50个完成工作流和任务唯一性。
6. 保存逐工作流R、R-0.9、风险预算消耗 `-ln(R)/-ln(0.9)`、逐任务实际rho及原始任务安排。逐任务频率不能当作独立训练重复。
7. 固定实际服务器放置、工作量，扫描请求rho=1.0/0.9/0.8/0.7/0.6/0.5；保留原能效频率下界，保存实际执行rho。只解析计算计算能耗、执行风险，**不报告扫描的deadline/ESP**，不冒充动态重调度或已训练固定频率基线。
8. 原始训练日志分析按各自阶段区分：探索中违约、可靠性惩罚、低层乘子、上层可靠性成本；区分整个训练历史与选定checkpoint之前的历史。SL续训单列，不能把后续训练作用归给更早选定模型。正乘子本身不等于实际非零惩罚。
9. 先用4个独立进程、每进程Torch线程1执行20次Full复放；不启动其他算法的新评估、不停止或恢复其他进程。禁止自动重启；已写的逐seed轨迹保留。完成需20个唯一seed、1000个工作流、所有原始指标核对、源hash不变及completion标记。

## 可用与不可用结论

- 可用：当前测试中是否存在可靠性余量；模型的频率—能耗—可靠性关系；训练阶段是否观测到约束激活。
- 不可用：可靠性模块的因果性能收益；真实硬件故障率校准；故障蒙特卡洛零失败；跨训练种子稳定性。
- 如果约束测试中宽松，应如实记录，不能为画出失败而提高故障率、改变任务、挑种子或悄悄抬高门槛。
- 如需证明可靠性模块独立贡献，另行设计同口径独立重训消融；本轮不启动。
