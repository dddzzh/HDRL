# Hierarchical D3QN-SAC 暂时无法超过 DQN-Edge 的问题说明

> 用途：将本文档直接交给网页端 ChatGPT 或其他研究者讨论。希望讨论的是算法的结构性问题，而不是继续盲目调 reward 权重。

## 1. 研究问题

当前研究对象是动态 Edge-Cloud 科学工作流调度。系统中多个工作流按照指数分布动态到达，每个任务需要完成两类决策：

1. 上层 D3QN 选择任务执行服务器；
2. 下层 SAC 为已选服务器连续输出归一化频率 `rho in [0.2, 1.0]`。

优化目标不是普通的加权多目标，而是：

```text
在满足工作流 Deadline 成功率约束的前提下，最小化系统总能耗。
```

目标 Deadline 成功率目前设为至少 99%。可靠性在当前无主备副本的实验中基本总能满足，因此当前主要矛盾是能耗与 Deadline。

## 2. 公平比较设置

以下结果使用相同的环境模型、资源配置、工作流生成方式和固定评估种子：

```text
工作流数量          = 20 / episode
数据集规模          = small
到达过程            = Cai 2025 exponential
arrival_rate        = 0.1
Edge / Cloud 数量   = 20 / 6
任务排序            = smallest_workload
备份副本            = disabled
固定评估种子        = 242000..242019
每个模型评估量      = 20 seeds x 20 workflows = 400 workflows
```

DQN-Edge 使用的是适配后的 `common_upper` 版本：

- 使用与本文上层相同的 347 维状态；
- 使用相同的任务到达、队列、通信、执行、能耗和 Deadline 模型；
- 动作为选择 26 个服务器之一；
- 固定 `rho=1`，不使用 DVFS；
- 使用两个独立 Q 网络分别学习时间和能耗；
- 使用 attention 网络产生候选服务器上的时间/能耗融合权重。

因此，当前差异的重点不是模拟器或输入 state，而是学习架构、reward 信用分配和是否使用 SAC。

## 3. 已验证的关键结果

### 3.1 DQN-Edge

| 模型 | 能耗 | Deadline 成功率 | 平均响应时间 | rho |
|---|---:|---:|---:|---:|
| DQN-Edge | **224.510 kJ** | **96.00%** | **37.155 s** | 1.000 |


### 3.2 本文算法中表现较好的版本

| 实验 | 能耗 | Deadline 成功率 | rho | 结论 |
|---|---:|---:|---:|---|
| 旧版 ep740 | 237.647 kJ | **99.00%** | 0.930 | 满足约束，但比 DQN-Edge 多耗 13.136 kJ |
| 20260818 ep460 | 242.129 kJ | 98.75% | 0.932 | Deadline 较好，但能耗更高 |
| 共享 lambda ep1420 | 244.125 kJ | **99.00%** | 0.947 | 约束满足，但策略更加保守 |
| 共享 state ep580 | 230.757 kJ | 95.00% | 0.884 | 能耗接近，但两个指标都没有超过 DQN-Edge |
| 冻结共享-state上层后训练SAC | 230.256 kJ | 96.25% | 0.888 | SAC微调没有产生明显优势 |

这里最关键的结论是：

```text
本文目前没有找到一个 checkpoint，能够同时做到：
energy < 224.510 kJ 且 Deadline success > 96%，
更没有做到 energy 更低且 Deadline success >= 99%。
```

旧版 ep740 在约束上明显更好，但能耗更高。较新的版本降低了一部分能耗，却又丢失了 Deadline。因此目前无法对 DQN-Edge 形成 Pareto 支配。

## 4. SAC 是否真的有用

为了排除“只看不同上层策略导致的假象”，我们把完全相同的 DQN-Edge 上层接到训练好的 SAC 上，并使用相同的20个种子做成对评估。

| 固定上层 | 下层 | 能耗 | Deadline | rho | 相对 rho=1 |
|---|---|---:|---:|---:|---|
| DQN-Edge | rho=1 | 224.510 kJ | 96.00% | 1.000 | 基准 |
| DQN-Edge | CTDE-SAC ep540 | 221.411 kJ | 90.50% | 0.921 | 节能1.38%，Deadline下降5.50个百分点 |
| DQN-Edge | 旧 SAC ep740 | **218.045 kJ** | 93.75% | 0.956 | 节能2.88%，Deadline下降2.25个百分点 |

证据文件：

```text
results/dqn_edge/20260824_091640/eval_with_ctde_sac_ep540_20seed.json
results/dqn_edge/20260824_091640/eval_with_old_sac_ep740_20seed.json
```

所以不能说 SAC 完全没有作用。它确实能在相同服务器选择下减少能耗，但目前的节能收益只有约1.4%到2.9%，同时造成更大的 Deadline 损失。

真正的问题是：

```text
SAC当前学到的是“降频能够省多少当前任务能耗”，
却没有准确学到“本次延长服务器占用会给后续任务和其他工作流造成多少排队代价”。
```

## 5. 当前算法为什么比不过 DQN-Edge

### 5.1 旧上层把两个本质不同的量塞进一个 Q 值

旧上层训练目标大致为：

```text
r_t^H = r_E,t^H - lambda_H c_t^H
```

其中能耗是要优化的目标，Deadline 是必须守住的约束。单个 D3QN 被要求同时逼近二者混合后的回报。

当 lambda 随训练变化时，同一条 replay transition 的有效目标也会变化。Q 网络必须持续追踪一个非平稳标量目标，容易出现以下现象：

- 前期学会满足 Deadline；
- 中期开始追逐能耗；
- lambda、策略分布和 replay 分布共同变化；
- 后期 Deadline 成功率再次下降。

DQN-Edge 恰好采用两个独立 Q 网络学习时间与能耗，再在动作选择时融合。它的两个 Bellman 目标更加稳定。这可能是它使用更小网络却能取得较好结果的重要原因。

### 5.2 上层训练标签和 lambda 更新指标曾经不一致

旧版本中，上层 replay 经常使用逐任务的增量时间成本：

```text
c_t^H = Delta C_t / D_w
```

但 lambda 更新使用的是工作流二元违约：

```text
c_w^H = I(C_w > D_w)
```

这两个量不完全等价。一个描述完成时间比例，另一个描述最终是否违约。结果是 Q 网络学习的约束价值与 lambda 想控制的成功率不是同一个随机变量。

### 5.3 上层和下层形成了非平稳串联环境

联合训练时：

- D3QN不断改变服务器分布；
- SAC不断改变任务执行时间；
- 执行时间改变服务器队列；
- 队列又改变D3QN下一步看到的状态和Deadline结果。

于是对上层而言，下层动力学一直变化；对下层而言，上层产生的数据分布也一直变化。普通独立 off-policy replay 会混合多个历史策略分布，使 Bellman 标签噪声进一步增大。

这也是分阶段训练、共享 lambda、C3C/HCC 和简单联合微调都没有稳定超过 ep740 的主要嫌疑，而不只是网络宽度不够。

### 5.4 下层动作造成的是全局队列外部性，但 reward 主要是局部的

SAC对当前任务降低频率后，会同时产生：

1. 当前任务动态能耗下降；
2. 当前任务执行时间增加；
3. 当前服务器更晚释放；
4. 后续任务排队时间增加；
5. 其他工作流的关键路径可能被拖慢。

第1项立即可见，第3至第5项延迟出现，而且可能由其他任务触发。当前 SAC 的局部 reward 和短期 transition 难以将后续工作流违约准确归因给早期的降频动作。

因此 SAC 倾向于输出约0.92到0.96的频率：确实省一点能量，但仍可能把处于边界的工作流推过 Deadline。

### 5.5 降频并不保证系统总能耗一定下降

服务器能耗包含静态功率和动态功率。降低频率后执行时间增加，因此可能出现：

```text
动态功率下降收益 < 静态功率持续时间增加 + 排队外部性
```

在这种服务器模型下，某些高效服务器使用 `rho=1` 本身就可能比低效服务器降频更省电。DQN-Edge虽然没有DVFS，但它可能通过更好的服务器选择已经获得了主要节能收益。

这说明本文不能把“rho平均小于1”本身当成贡献，必须证明相同上层策略下 SAC 的系统级总能耗显著下降，并且 Deadline 约束仍然成立。

### 5.6 347维 state 不是唯一问题

DQN-Edge的 `common_upper` 也使用相同347维 state，却取得更好的能耗/Deadline折中。因此简单地继续删减或扩充上层 state，未必能解决根本问题。

更可能的差异是：

- DQN-Edge对时间和能耗分别建模；
- attention在动作层面进行状态相关融合；
- 本文旧D3QN使用一个混合Q；
- 本文又叠加了下层SAC造成的非平稳执行时间。

### 5.7 checkpoint 规则需要完全统一

本文模型当前按以下规则选择 checkpoint：

```text
先要求 Deadline >= 99%，满足后选择能耗最低。
```

DQN-Edge训练程序当前主要根据组合 episode reward 保存 best checkpoint。最终论文比较前，所有算法应使用同一组独立验证种子和同一个约束优先 checkpoint 规则，否则会混入模型选择偏差。

不能通过故意削弱 DQN-Edge 来取得优势；正确做法是统一模型选择规则，然后提升本文方法。

## 6. 已尝试但没有根治问题的方向

已经尝试过：

- 上下层直接联合训练；
- HEFT预训练SAC，再训练D3QN，再联合微调；
- 冻结D3QN单独训练SAC；
- 上下层共享或不共享Deadline lambda；
- 共享上下层state；
- 本地Actor加全局Critic的CTDE-SAC；
- 责任感知 replay；
- C3C/HCC 第三协同评价网络；
- 子任务 Deadline；
- 调大固定 Deadline 惩罚；
- 修改能耗权重与 lambda 学习率。

这些实验说明：继续给 reward 加一个系数、继续加第三个网络、或者单纯增大隐藏层，不足以解决问题。

## 7. 当前正在验证的新方向

现在新增了一个独立的上层双头约束 D3QN，先固定 `rho=1`，不接SAC：

```text
Q_E(s,a) = 服务器选择的累计能耗收益
Q_D(s,a) = 工作流最终违约风险

a_t = argmax_a [Q_E(s_t,a) - lambda_H Q_D(s_t,a)]
```

两个网络使用独立 Bellman 标签：

```text
y_E = r_E + gamma_E Q_E_target(s_next, a_next)
y_D = c_D + gamma_D Q_D_target(s_next, a_next)

a_next = argmax_a [Q_E_online(s_next,a) - lambda_H Q_D_online(s_next,a)]
```

Deadline 标签改为最终工作流二元违约，并按照每个任务的非负 `Delta C_t` 分配：

```text
c_w = I(C_w > D_w)
c_t = c_w * Delta C_t / sum_j Delta C_j
sum_(t in workflow w) c_t = c_w
```

lambda只参与动作选择，不进入两个Q头各自的监督标签：

```text
lambda_H <- clip(lambda_H + eta * (mean_w(c_w) - 0.01), 0, 100)
```

这个实验的目的不是立刻加入新复杂度，而是回答一个明确问题：

```text
在没有SAC非平稳性的情况下，分离目标Q和约束Q，
能否先得到 energy < 224.510 kJ 且 Deadline >= 99% 的上层策略？
```

如果不能，问题主要在上层服务器选择、环境可行边界或能耗模型；如果能，再讨论怎样在不破坏约束的情况下接入SAC。

## 8. 希望讨论者重点回答的问题

请不要只建议“调大惩罚”“增加网络层数”或“多训练一些episode”，希望重点回答：

1. 对于“最小化能耗、Deadline成功率至少99%”的CMDP，使用独立 `Q_E` 和 `Q_D`，再通过 `Q_E-lambda Q_D` 选动作是否数学上合理？
2. `Q_D` 应学习逐任务增量时间、最终二元违约概率，还是二者的组合？怎样保证它与工作流级 lambda 更新严格一致？
3. 二元违约标签非常稀疏。将一次工作流违约按 `Delta C_t` 分配给任务是否会产生错误归因？是否应该使用 n-step return、distributional risk critic 或 eligibility trace？
4. 下层SAC的频率动作会影响未来队列。怎样在不增加第三个大型网络的情况下，让SAC获得系统级延迟责任信号？
5. 是否应把SAC改为学习相对于安全频率 `rho_safe` 的残差，而不是直接输出绝对rho，从结构上避免破坏Deadline？
6. 是否应先训练一个满足99%约束的上层，再把SAC限制在不改变上层可行性的安全动作域中？这仍然算联合优化，还是只算串联优化？
7. 为什么固定 `rho=1` 的DQN-Edge已取得224.510 kJ，而使用DVFS后只能额外节约约1%到3%？这个幅度是否由当前静态/动态功率模型决定？
8. 应设计哪些最小消融实验，才能区分问题来自上层服务器选择、SAC信用分配、lambda更新、reward尺度或系统本身的可行Pareto边界？

## 9. 当前最需要的判断

目前最需要的不是再提出一个复杂模块，而是判断以下三种情况中的哪一种成立：

```text
A. 上层单Q混合目标是主要瓶颈，双头约束D3QN可以解决；
B. 上层可以解决，但SAC的全局队列信用分配错误；
C. 当前服务器功率和Deadline配置下，满足99%后本来就几乎没有DVFS空间。
```

只有先用成对实验区分 A、B、C，才能决定论文创新应该放在“约束服务器选择”“跨层信用分配”还是“安全DVFS动作参数化”上。
